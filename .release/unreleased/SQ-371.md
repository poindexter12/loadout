ref: SQ-371
title: Gateway fixture processes no longer fail "could not confirm the owner" under host load (test-only change)
bump: patch
plugins: [model-gateway]
---

Four more tests failed whenever the host was busy: `ensure writes the discovery cache before reporting missing ChatGPT auth`, `sibling ensure retires dead records without deleting replacement worker and proxy records`, `cache-junction gateway process is preserved as a foreign port owner`, and `setup restart path refuses a foreign shim before it can restart its worker`. Each one runs `ensure`, `stop`, or a restart that first confirms which process owns the gateway port with real `netstat`, `lsof`, and `ps` calls. Under load those calls overran the default 2 second limit, the owner came back unknown, and the command refused before the behavior under test ran. The shared test fixture now gives every gateway process it spawns a 60 second probe limit, and a new test checks that the limit reaches the child and can still be lowered by a test that exercises the timeout refusal. The owner check is still real. Shipped plugin behavior is unchanged.
