---
ref: SQ-318
title: "sidequest: let scopeRequest rule instead of refusing every call with \"refused undefined\""
bump: patch
plugins: [sidequest]
---

Any `scopeRequest` that auto-approved at least one path refused with `declared file scope: refused undefined; only null is implicitly writable`, and named the requesting ticket's own declared release fragment as foreign. The scope-expansion write re-validated the merged declaration through the same bound as `add` and `update`, but passed no context, so the foreign-release-fragment guard ran with no requesting ref: every `.release/unreleased/*.md` entry already declared on the ticket was classified as somebody else's, and the error threw before the real request was ever ruled on. Two executors hit it 2/2 on tickets that declared their own fragment, which is the normal shape, so no executor could self-serve scope at all and every grant had to go through the orchestrator with `update`.

The scope-expansion write now carries the ticket's ref, slug, category, and readonly override, exactly like the declaration paths, so a ticket's own fragment is never foreign and a readonly ticket's declared external output is no longer refused on a scope expansion. The refusal text also no longer interpolates a hole: a caller that loses the ref names the subject in prose rather than printing `undefined` and `null`, and a genuinely foreign fragment's refusal names both the requesting ticket and the fragment's owner.
