---
ref: SQ-276
title: "sidequest: a widened directory scope no longer sweeps another ticket's uncommitted work into a commit"
bump: patch
plugins: [sidequest]
---

A declared scope entry goes to Git as a pathspec, so a directory entry staged and committed every changed path beneath it. An auto-approved test-scope widening turns one requested file into its enclosing test root, which meant a ticket's `commit` could carry work it never made: in the reported case (nexia SQ-42, 2026-10-07) one commit took a second live claim's uncommitted test file plus a third ticket's report-only tests that depended on uncommitted source changes, and removed them from the working tree. The commit returned `ok:true` with `unscopedPaths: []`, because the swept paths were inside the widened scope rather than outside it, so the executor was told nothing and the orchestrator had to soft-reset and rebuild the index by hand.

A scoped commit now subtracts the paths the board can prove are not this ticket's work, as `:(exclude)` pathspecs on both the staging and the commit: paths another live claim's execution scope covers, and paths whose dirty-baseline identity has not moved since the dispatch launched. Only paths that entered scope through a directory or glob entry are eligible, so an exactly-declared file is never stripped from the commit that was dispatched to change it, and an isolated worktree is left alone because nothing in it belongs to another claim. A foreign staged path stays staged, a foreign untracked file stays untracked, and a foreign deletion stays uncommitted. The commit reports what it left behind and who owns it, and a commit whose scope holds nothing but foreign changes is refused as `no_own_changes` naming those paths and their owning refs, instead of surfacing the contentless `git commit --only` failure it used to.

This catches sibling-executor work and pre-dispatch dirt. It does not catch a human editing a file in the widened directory mid-run, because the board records no per-executor write log.
