---
ref: SQ-390
title: The repeated-command hook tests own their counter store instead of sharing the host's
bump: patch
plugins:
  - sidequest
---

The repeated-command warning hook keeps its per-agent counter in a host-global directory,
`<os.tmpdir()>/sidequest-repeated-command-warn/<encodeURIComponent(agent_id)>`, that nothing ever
clears. Its tests keyed that store by `repeated-command-${Date.now()}`, a key that is neither
unique (one millisecond of resolution) nor private to the test, so the test silently depended on no
other process on the host having written the same name. When something had, the counter already
held two hits and the test's first call warned where it asserts silence, which is how main-push run
41333570717 failed `pre-tool repeated-command hook warns on the third repeat and every fifth after`
on a tree that passed on rerun. Each repeated-command test now takes a `randomUUID` identity and
redirects the hook's `TMPDIR` to its own fresh directory, so the store it counts in starts empty
whatever the host holds. A new regression test seeds the host store with exactly the two-hit state
CI must have had and asserts the hook still counts from one, so the isolation cannot quietly be
removed again.
