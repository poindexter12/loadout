# codebase-mapper changelog

Generated by `scripts/release/cut.mjs`. Versions before the first entry below are in `git log`.

## 2.17.0 (2026-10-10)

Released in v4.10.0, up from 2.16.1.

### Features

- codebase-mapper hook: detect graph mode and point agents at graphify for structure (SQ-310) [`5f0c3ca`](https://github.com/poindexter12/loadout/commit/5f0c3ca9799a9dd66f2463b551f270b71074b7a2)
  Hooks detect graphify-out/GRAPH_REPORT.md and, in graph mode only, send structural questions to graphify query/explain/path while the narrative docs stay the source for conventions, patterns and onboarding. Subagents are also forbidden to run graphify --update. A .map-state.json declaring structure: "graphify" covers narrative docs only, so the retired modules/entry-points/directory-structure docs no longer read as stale. Projects without a graph report are unaffected, byte for byte.
- map-codebase: build a codebase map in graph mode, with graphify owning structure (SQ-311)
  The map-codebase skill can now build a map in graph mode. It detects the `graphify` CLI and an existing `graphify-out/GRAPH_REPORT.md`, and when the CLI is there with no graph yet it offers the first build with the cost stated honestly: the AST pass over code is deterministic and free, while the semantic pass over docs, papers and images runs on the session's LLM, so a large `docs/` tree costs real tokens and a code-only repo costs nothing. It then offers `graphify hook install` for the deterministic post-commit rebuild, and names `graphify update .` as the manual fallback if that hook is declined. `graphify claude install` is forbidden by name, under the existing never-touch-CLAUDE.md rule.

  In graph mode the skill stops writing `modules.md`, `entry-points.md` and `directory-structure.md`, traces key flows with `graphify query`, `path` and `explain` instead of walking the tree by hand, records `structure: "graphify"` in `.map-state.json`, and ignores `graphify-out/` except for the tracked `GRAPH_REPORT.md` and `graph.json`. `dependencies.md` is unaffected, since it comes from package manifests. The INDEX template gains a compact Structure section pointing at the graph and its three commands: structure questions go to the graph, convention questions go to the docs. Without the CLI nothing changes; graph mode is opt-in and the mapper works exactly as before.
- update-codebase-map: graph-mode freshness split and one-time conversion of an existing map (SQ-312) [`b9b1769`](https://github.com/poindexter12/loadout/commit/b9b1769836b4b9fe131fcb3a1a84572395f834fc)
  Refreshing a map in graph mode no longer asks the model to re-derive structure. Changed code files belong to graphify: the skill checks `graphify hook status`, confirms `graphify-out/GRAPH_REPORT.md` is no older than the last commit when the post-commit hook is installed, and otherwise runs `graphify update .` exactly once. The model then assesses narrative impact only, so a refactor that moves files without changing a convention, a pattern, an architectural boundary, an entry point's story or an onboarding step is a no-op. The three retired structural documents stay out of the rebuilt `documents` list and hash manifest, and subagents still never refresh the graph or the map.

  A new "Converting an existing map to graph mode" section handles a map built before the graph existed: when a graph report is present but `.map-state.json` has no `structure`, the skill offers one announced conversion that rescues any narrative sentences worth keeping, removes `modules.md`, `entry-points.md` and `directory-structure.md`, rewrites the INDEX structure section to point at graphify, and rehashes with `structure: "graphify"`. Classic maps with no graph report behave exactly as before.

### Fixes

- codebase-mapper: --structure graphify on write-map-state and the hook names the documented refresh form (SQ-317) [`cda9bc8`](https://github.com/poindexter12/loadout/commit/cda9bc8ed407a51a0f73996702bc0f5d4ccb66a4)
  Recording a graph-mode map was two commands: the bundled state writer, then a `node -e` one-liner that put `structure: "graphify"` back, because the writer rebuilt the state object from scratch and dropped the field. `scripts/write-map-state.js` now accepts `--structure graphify`, so both map skills record the mode in the one command they already run. `graphify` is the only accepted value: a typo exits non-zero with the value quoted and leaves the manifest untouched, rather than writing a manifest no hook recognizes.

  Without the flag the writer now preserves whatever `structure` the manifest on disk already declared, including a value a newer plugin wrote, so a plain refresh can no longer demote a graph-mode map back to classic and make a session report the retired structural documents as drift.

  The SubagentStart context line forbade only `graphify ... --update`, the undocumented alias. It now names the documented `graphify update <root>` first and still forbids the alias, because both spellings work at graphify 0.8.38 and a subagent must run neither; the update-codebase-map subagent rule repeats that wording verbatim.

## 2.15.5 (2026-08-17)

Released in v3.477.0, up from 2.15.4.

### Fixes

- Test fixtures pin their initial git branch, and a guard keeps them pinned (SQ-2201)
  `git init` takes its branch name from `init.defaultBranch`, and the full suite runs with global and system git
  config nulled out, so the same fixture started on `main` under `npm run test:files` and `master` under
  `npm run test:full`. A fixture that later named a branch did not fail cleanly there: `git checkout main` with
  no local `main` and an `origin/main` present creates a local branch tracking the remote, so the assertions ran
  against a tree the fixture never built. That cost two full-gate failures whose entire output was two
  unexplained shas.

  Every git fixture across both suites now passes `-b main` to `git init` (43 call sites), and a new guard test
  scans the sidequest test directory for a `git init` that inherits the ambient default. A test that is
  deliberately about the unconfigured default opts out with an `unpinned-initial-branch: <why>` comment, which
  is how the one honest case, the assertion that the full suite has no default branch configured, stays.

## 2.14.1 (2026-08-06)

Released in v3.403.0, up from 2.14.0.

### Fixes

- Delete tests that pinned wording instead of behavior (SQ-1238)
  715 assertions across four plugins checked that documentation said something in
  one particular arrangement of words. They failed when a paragraph was rewrapped
  and passed when a claim was reworded away, so they cost suite time and release
  diagnoses without protecting anything. They are gone.

  17 assertions survive, and each guards something a user or caller actually
  depends on: a banned instruction that must never reappear, a threshold on a real
  cost, a contract a descriptor has to convey. Those now assert the mechanism
  rather than the sentence, matching whitespace-tolerantly where only text can
  express the claim.

  The worst habit this removes is not the wasted time. It is that shipped prose was
  being edited to satisfy a regex, which lets a test quietly start writing the
  documentation.

## 2.14.0 (2026-08-06)

Released in v3.388.0, up from 2.13.0.

### Features

- codebase-mapper ships its map-state writer instead of describing it (SQ-1360)
  update-codebase-map asked the model to rewrite `.map-state.json` with today's date, the current commit, the document list, and SHA-256 hashes of every document's exact final bytes. That is mechanical work described in prose, so every workspace wrote a script for it and got to reintroduce the same bugs. On Terge_VST the orchestrator wrote its own `write-map-state.js` and invoked it twelve times, hand-patching a hardcoded document list as documents changed.

  `plugins/codebase-mapper/scripts/write-map-state.js` now ships with the plugin, taking `--project <dir>` the way live-rules' `sync-atomic-rules.js` does. It discovers documents from the map directory rather than a hardcoded list, reads the current commit (null outside a repository), and replaces the state file last. Both map skills invoke it instead of describing the computation.

## 2.13.0 (2026-08-06)

Released in v3.387.0, up from 2.12.3.

### Features

- Workspace rule templates stop producing a permanent manifest mismatch (SQ-1359)
  Two defects that hit every workspace `init-workspace` sets up, both found the hard way on Terge_VST.

  The live-rules reference doc's example manifest entry omitted `priority` and `include`. `sameManifestEntry` compares a missing `priority` as 0 against the rule's actual 95, so every entry written from our own template mismatched, and the workspace got a manifest-mismatch warning injected on every prompt. The template now carries the fields the comparison reads.

  Hashes were computed over raw bytes, so a CRLF checkout of the same rule file hashed differently from an LF one and the manifest never matched. Both live-rules and codebase-mapper now normalize line endings before hashing, which also means a map or manifest built on one platform still verifies on another.

  Fixture hook spawns in the live-rules tests now pin `CLAUDE_PROJECT_DIR` to the fixture directory. The hooks prefer that variable over the fixture cwd, so 13 tests read the real repository's rules and failed whenever it was set — invisible in CI, which never sets it, and a phantom red for anything run from inside a session.

## 2.12.3 (2026-08-03)

Released in v3.351.0, up from 2.12.2.

### Fixes

- The map update instruction told the model to end its turn, so the skill never ran (SQ-1295) [`be65277`](https://github.com/Eigenwise/eigenwise-toolshed/commit/be652774)
  The injected instruction said to "end with" the line announcing that the map update is running. A turn that has ended cannot contain the tool call that was supposed to follow, so sessions closed on "Running /codebase-mapper:update-codebase-map" and the map never got updated. It read as done to anyone skimming, which is how it survived. The announcement now comes before the action and says outright that announcing is not doing, and a Stop hook blocks the turn when the claim was made without the skill actually being invoked. The block skips subagents, skips the "no updates needed" ending, and won't fire twice in a row.

  Subagents started with no map and re-read it by hand: 851 orienting reads costing ~134 min and ~4.44M fresh tokens across 58 transcripts in four days, with modules.md itself among the most re-read files.
