title: Verify-capture names the Bash timeout a long capture needs
bump: patch
plugins:
  - sidequest
---

The verify-capture wrapper now announces, before the command starts, the Bash timeout a caller must pass if it backgrounds the wrapper: the capture budget plus a 600000ms margin, at most the 7200000ms harness maximum. A budget at or above the harness's 1800000ms background default says outright that a backgrounded call without an explicit timeout is killed before any verdict is recorded, and a budget too close to the maximum for any timeout to outlive it points at `--detach`. The closing `capture-budget` line carries the same value as `harnessTimeoutMs`. Executor briefings state the rule once: never count on a foreground timeout for a gate that may pass ten minutes, and an attached capture that may is backgrounded with an explicit 7200000 timeout, never the default.
