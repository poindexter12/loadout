ref: SQ-183
title: Stop telling the orchestrator to TaskStop executors; model-gateway update no longer fails on an unconfirmed shim owner
bump: patch
plugins:
  - sidequest
  - model-gateway
---

Sidequest no longer tells the orchestrator to retire finished executors with `TaskStop({ task_id: "<agent name>" })`. The dispatch name is a `SendMessage` address, not a `TaskStop` task id, so the call returned "No task found with ID" or raised a permission prompt the user rejected. SubagentStop verdicts, SessionStart guidance, the TaskOutput guard, and the skill now say never to `TaskStop` an executor.

`model-gateway update` no longer reports FAILED when the shim supervisor's :18764 owner cannot be confirmed: the restart is deferred to the next ensure and the healthy listener is left running. A foreign-install owner or a failed stop still fails the update.
