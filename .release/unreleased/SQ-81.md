---
ref: SQ-81
title: A green capture survives a release-fragment-only follow-up commit
bump: patch
plugins: [sidequest]
---

Committing `.release/unreleased/<REF>.md` after a green verify-capture no longer forces a full re-run. Submit now carries an earlier capture (and any capture waiver bound to it) forward to the submitted candidate when the captured commit is an ancestor of that candidate and every path in the diff between them sits under `.release/unreleased/`. The carry is checked with git at submit time, not trusted: a follow-up that touches any other path, including a fragment plus a source file in one commit, still requires a fresh capture. The `verification_capture_required` refusal now says so.
