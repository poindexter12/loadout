ref: SQ-367
title: Keep verify-capture's fixture gateway catalog fresh through a long full-suite run
bump: patch
plugins:
  - sidequest
---

`test/verify-capture.test.ts` plans Codex dispatches roughly eight minutes into the full suite's
functional phase, past the five-minute freshness window the suite's one-shot fixture catalog is
stamped for, but it never opted into the shared `_gateway-catalog-freshness` hook that re-stamps
seeded catalogs between tests. Its readiness therefore survived only when another test file's hook
happened to re-stamp the shared catalog recently enough; when that timing slipped, `prepareDispatch`
refused with "model-gateway readiness is unavailable" and failed the release cut while the real
gateway was up and ready. The file now takes the opt-in, and a new suite proves it by pointing
discovery at a catalog already stamped outside the window and requiring readiness and dispatch
planning to work anyway.
