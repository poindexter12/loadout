ref: SQ-40
title: "sidequest: test fixtures resolve the temporary-directory symlink before a child process can disagree about them"
bump: patch
plugins: [sidequest]
---

No change to anything Sidequest does at runtime. This is test infrastructure, and it is in the changelog only because the files live under a published plugin.

On macOS `os.tmpdir()` reports a path through the `/var` symlink while a child process reports the `/private/var` target of it, so a fixture directory created with `fs.mkdtempSync()` and then compared against a spawned process's working directory does not match, for reasons that have nothing to do with the behavior under test. That class of failure was fixed once already, inline, in Quartermaster's workspace bootstrap end-to-end test. The repository now has a shared helper for it, `tmpFixture(prefix)` in `plugins/test-support`, which creates the directory and returns its canonical path, shared the same way the Windows process-visibility helper is.

Sidequest's test home adopts it, for both `SIDEQUEST_HOME` and the `SIDEQUEST_AGENTS_DIR` added by SQ-316. Adoption elsewhere is deliberately left alone: several hundred other fixture sites across the repository still create their directories directly, and rewriting them was an explicit non-goal rather than an oversight. The helper carries its own regression test, which points the temporary root at a symlink it creates so the check fails on a non-canonicalizing implementation on Linux as well as on macOS.
