---
ref: SQ-330
title: A dispatch prompt and a briefing print the scope the gate enforces, not the ticket's declared list
bump: patch
plugins: [sidequest]
---

A ticket filed with no `files` and dispatched with `allowUnscoped` told its executor "Declared files: (No files were declared.)" while `pulse` on the same ticket reported an enforced scope of `docs/`, which `defaultAlwaysInScope` derives from the repository layout and which no ticket can opt out of. Two surfaces disagreed about one fact, and the executor had no reason to doubt the one it was handed. On SQ-329 it wrote nine implementation files under `plugins/quartermaster/`, met the commit gate's refusal at the end of the run, and had to hand the work back as a preserve commit.

The disagreement was structural: both the spawn stub and the briefing printed `ticket.files` alone, so everything the board added on top of the declared list, the always-in-scope paths and the ticket's own release fragment among them, was invisible to the agent the gate would later refuse.

Both surfaces now print one list, and it holds the set the gate admits rather than the set someone typed. A live dispatch binding is authoritative, because that binding is exactly what `pulse` returns as `scope.enforced`; without one, the ticket's commit scope is shown, which is what `pulse` returns as `scope.declared`. Both readings are taken the way `scopePulse` takes them, so the two surfaces cannot drift apart again. Any path in that set the ticket did not declare is marked `(board-inferred)`, so an executor can tell a derived path from a declared one without reading the board's configuration, and a list carrying one closes with the fact that matters: writes and commits are gated on exactly these paths. A ticket that declared nothing says so first. When the declared list already is the enforced set, which is the common case, the text is unchanged.

The list is deliberately compact, because it also rides the `dispatch` tool's response, which the context budget benchmark holds to 1320 bytes. The first draft printed a declared list and an enforced list and overran that ceiling by 56 bytes, which is its own argument for stating the scope once.

One narrower disagreement went with it. The implicit release fragment line called `store.commitScope`, which `store.ts` passes into its layers but has never re-exported, so the read was `undefined` and the optional chain deleted the line instead of raising. Every briefing and dispatch prompt had been silently omitting that fragment since the line was written. It is not revived as its own paragraph, which the budget has no room for: the fragment is one of the enforced paths and is now listed and annotated there, for the tickets whose scope actually admits it.
