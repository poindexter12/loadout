---
ref: SQ-452
title: "Working-tree inspection no longer fails with ENOBUFS on a tree whose git status output exceeds 1 MiB"
bump: patch
plugins: [sidequest]
---
Sidequest's scoped-commit and working-tree inspection read `git status` and other git output through a 64 MiB buffer instead of Node's 1 MiB default. A shared tree with large untracked directories previously threw ENOBUFS, so `done` and every working-tree delivery inspection refused `working_tree_delivery_unavailable` whatever the ticket's own changes were. The status read still covers the whole tree with every untracked file listed, because its callers check for unscoped and foreign paths.
