---
ref: SQ-385
title: Wave assembly judges a candidate's real base when its recorded baseline was rolled back
bump: patch
plugins:
  - sidequest
---

A dispatch baseline can name a commit the integration target no longer contains: a release cut commits on local `main`, fails its gate, and resets `main` back, and a rework reuses the first attempt's baseline. Wave assembly compared only that record, so candidates whose commits already sat on the restored target were refused `baseline_moved` and each needed a code-unchanged redispatch.

Assembly now falls back to the candidate's real base when the recorded baseline resolves to a commit the target cannot reach: the candidate is admitted when it no longer carries that unreachable commit and shares history with the target, and its submission is rebaselined in place onto the real base with `rebaselinedFrom` provenance, so no redispatch is needed. A baseline that resolves to no commit at all still refuses, and the `baseline_moved` message now names the rebase-and-resubmit recovery instead of implying a redispatch moves the baseline.
