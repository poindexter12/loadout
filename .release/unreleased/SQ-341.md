ref: SQ-341
title: The no-pinned-command capture test files its ticket the way production does, so SQ-319's empty-verify refusal no longer breaks it
bump: patch
plugins: [sidequest]
---

SQ-319 refuses an explicitly declared `command` verify kind with an empty command at the source, which broke the SQ-203 test covering the capture recorder's no-pinned-command branch: that test declared the kind deliberately in order to reach the branch.

The branch is still reachable and the refusal is unchanged. An omitted verify kind still defaults to `command`, so a ticket filed before its verifier is known is stored with kind `command` and no command at all, which is the state the recorder's no-pin message exists for. SQ-319 guards what a caller declares, not what the store holds. The test now files its ticket that way, and asserts the stored shape it depends on so a change to that default fails loudly instead of quietly recasting the test.

No behavior change: the recorder's refusal, its message and SQ-319's validation are all untouched.
