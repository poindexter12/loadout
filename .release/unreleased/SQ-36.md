---
ref: SQ-36
title: "model-gateway: the dead Windows code paths are gone, and the platform-independent logic they hid behind is now tested on the platform that runs it"
bump: minor
plugins: [model-gateway]
---

Windows stopped being a supported platform on 2026-09-15, and CI stopped building it in the same change. The Windows code in this plugin kept being carried anyway: a `WIN` constant exported from `runtime.js` and read at 52 sites across `lib/`, a `taskkill` process-tree killer with its own close-wait loop, PowerShell CIM queries for process inspection, a `netstat` table parser for port ownership, an entire `lib/windows-detached.js` module for reparenting a detached child through a VBScript shim, and `.exe` and named-pipe branches in the binary and socket paths. None of it ran on a supported platform, none of it was exercised by CI, and all of it had to be read and reasoned about by anyone touching process supervision. The audit grep the ticket asked for -- `win32|taskkill|PowerShell` over `plugins/model-gateway/lib` -- goes from 15 matches to 2, and the `WIN` constant from 52 references to none. The two survivors are in `settings-wiring.js`, where they case-fold a resolved path before comparing it against a settings registry key; that is path normalization rather than a Windows code path, and it sits outside this change's declared files.

What made this more than a deletion is that some of the removed code was the only caller of logic that is not Windows-specific at all, and some of the removed tests were the only coverage of it. Three tests simulated `win32` to reach behavior that every platform shares, so the simulation went and the assertions stayed, re-pointed at the real platform. Probe children are still asserted to be spawned detached so a timed-out probe can be signalled as a group, and to have their piped stdout accumulated across chunks rather than read once; that test now drives the POSIX `netstat` and `ps` parsers, which also gives `processInfoAsync` its only direct coverage. Probe shutdown is still asserted to signal the whole probe group and wait for the child to close, now through the POSIX path instead of `taskkill`. The SQ-23 regression guard -- that a healthy shim on the current version makes `ensure` surface a real missing-auth failure instead of an unconfirmed-owner refusal -- keeps its assertion, moved onto the test that already covered the same flow for real.

The comments explaining why the old code was wrong are deliberately still here. Two record SQ-266, where a teardown reached for `taskkill` on every platform and leaked a process tree for seven days; one records an `ensure`-lock race first observed on Windows CI. The platform is gone but the races are not, and each of those notes documents a bug that a supported platform can still have.
