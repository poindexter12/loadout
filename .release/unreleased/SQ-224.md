---
ref: SQ-224
title: "sidequest: deny a pattern-selected kill that would reach another executor's verify run"
bump: minor
plugins: [sidequest]
---

One executor clearing what it took to be its own stuck `cargo test` killed a different ticket's verify run in another worktree. No in-plugin code path did it: `lib/ports/process.js` only ever terminates the process group it spawned itself, and every other signal site is an own child or a `kill(pid, 0)` liveness probe. The kill came from the executor's own shell, and nothing refused it. The eight PreToolUse `Bash|PowerShell` guards were 32/32 silent-allow against `pkill -f cargo`, `kill -9 <pid>`, `killall -9 node` and `ps | grep | xargs kill -9`, and the "Sibling liveness" rule in the executor instructions forbade exactly one cross-executor stop verb, `TaskStop`, and said nothing about OS signals. So an executor that decided a test run was its own reached for Bash and violated no rule that existed.

The mechanism is target selection rather than the signal. `pkill -f` matches on command line, and parallel executors on one host run byte-identical test commands, so such a signal crosses every worktree by construction. A new `guard-process-signal` PreToolUse guard denies a kill that selects by pattern or by search (`pkill`, `killall`, `taskkill /IM`, `Stop-Process -Name`, a `Get-Process`-fed `Stop-Process`, anything through `xargs kill`, and a `kill` whose target came from a `pgrep`/`ps` substitution or from a variable assigned one), and its refusal names the two legitimate routes, because the whole defect was an executor not knowing them: a verify run that overruns its budget is terminated by the verify wrapper, which kills the process group it spawned, and a task you started is stopped with `TaskStop`. The same rule now appears in the executor instructions, extended from `TaskStop` to OS signals, and is regenerated into every bundled executor agent.

An own-shell kill stays allowed, since that form is own-attempt by construction: `kill %1`, `kill $!`, `kill "$pid"`, `kill "$(cat run.pid)"`, `taskkill /PID`, `Stop-Process -Id`, and read-only `pgrep`/`ps`. A literal `kill 48213` also stays allowed, because no text guard can distinguish a pid this attempt spawned from one read out of someone else's `ps` output; the instruction covers that case, and making it checkable needs the verify shell's process group recorded in the capture slot, which today holds only the wrapper's own pid.
