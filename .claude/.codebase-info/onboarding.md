# Onboarding

Last Updated: 2026-10-10

1. Read `README.md`, `CLAUDE.md`, and this map index. `CLAUDE.md` contains repository rules for generated docs, prose docs, and synthetic screenshots.
2. Identify the surface: Sidequest engine/dashboard, Quartermaster, Observability, Model Gateway, Live-rules, Codebase Mapper, shared test support, docs, the local-only Windows Sandbox harness, or release automation. Ask the graph where it lives rather than hunting the tree: `graphify-out/GRAPH_REPORT.md` for the overview, then `graphify query "where does execution start"`, `graphify explain "<module>"`, and `graphify path "<from>" "<to>"`. This map no longer carries a folder tree, an entry-point list, or a module catalog; the graph owns all three. If `graphify` is not installed, it is an opt-in `uv` tool and Quartermaster's setup can add it, but the committed `graphify-out/GRAPH_REPORT.md` and `graph.json` already answer most questions as plain files.
3. For Sidequest runtime work, read `plugins/sidequest/package.json`, `plugins/sidequest/scripts/build.mjs`, and `plugins/sidequest/scripts/generate-bundled-agents.mjs`, then the relevant source module. Remember manifests load committed `agents/`, `lib/`, `bin/`, and `hooks/` output; normal session-start maintenance migrates marked legacy generated agents instead of recreating them.
4. For Sidequest lifecycle work, start with `plugins/sidequest/src/lib/kernel/`, including `kernel/review-binding.ts` and `kernel/worktree.ts` (whose `checkoutLayout` export keeps checkout identity off process spawns), then follow the adapter into `store/dispatch.ts`, `store/submissions.ts`, or `worktrees.ts`. If you are touching a hook, measure before adding a probe: these paths run against a ~10s deadline and spawns, not queries, are what exhaust it. `prepared-dispatch.ts` canonicalizes prepared executor identity, and `source-revision-capability.ts` binds immutable non-Git candidates to their dispatch baseline. Frozen briefing snapshots are continued with the `context_page` MCP tool.
5. For Model Gateway work, start at `plugins/model-gateway/README.md` and `plugins/model-gateway/bin/model-gateway.js`; use `doctor` and readiness/catalog checks when verifying local setup. Sidequest consumes only fresh schema-4 catalogs whose provider readiness is true. Shared-proxy recovery belongs in `lib/process-supervision.js` and `lib/request-worker.js`, not in project-specific startup hooks. Same-marketplace/plugin cache siblings may be replaced during upgrade, while foreign or non-cache processes stay untouched. Any per-model window or compaction number comes from `lib/runtime.js` `resolveGatewayModelPolicy`; never add a second copy. When the gateway "died", read `doctor`'s lifecycle evidence before theorizing. If a project's settings already point `ANTHROPIC_BASE_URL` at something that is neither this gateway nor an Anthropic endpoint, setup and ensure decline to wire it rather than overwriting; expect the decline and the notice naming that endpoint, and do not "fix" it by forcing a write.
6. Run the narrow package check or test command documented in that package before broad suites. Sidequest scripts include `typecheck`, `build:check`, `test:files`, `test:full`, and `test:perf`; dashboard has `check`, `test`, `build`, and `e2e`; Quartermaster setup validates the Sidequest registry, derives routing profiles, requires an explicit worktree-isolation choice, applies profiles/worktrees in Phase 4, and checks effective `autoCompactWindow`; setup may offer 325000 when unset, while doctor reports it read-only. Its update skill uses the stable Model Gateway updater. Docs uses `npm --prefix docs run check`, and `npm --prefix docs run build` on top of it whenever a page or sidebar entry is added, renamed, or removed, because `check` passes on a sidebar slug whose page no longer exists; the sandbox contract uses `pwsh -NoProfile -File sandbox/windows/Test-ToolshedSandbox.ps1`.
8. For user-facing changes, update affected prose docs in `docs/src/content/docs/` or file the linked docs-writing ticket. Never hand-edit generated reference pages.
9. For plugin changes, update both plugin manifest and marketplace version fields through the release process. See [release and publishing](release-publishing.md).

Keep `.claude/.codebase-info/.map-state.json` last when refreshing this map, and keep its `structure: "graphify"` field, which is what makes the hooks read the retired documents' absence as deliberate rather than stale. The state writer records it in one command, `write-map-state.js --project . --structure graphify`, and preserves it on later plain runs, so there is no separate step to remember.
