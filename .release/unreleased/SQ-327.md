---
ref: SQ-327
title: Executors keep scratch files in a per-dispatch directory
bump: patch
plugins:
  - sidequest
---

Every executor a session spawns is handed that session's one scratchpad, so concurrent executors writing the same generic filename (for example `negative-control.js`) overwrote each other mid-dispatch, and a source file swapped out for a control could be restored from another dispatch's copy. Executor briefings now name a per-dispatch scratch directory, `<scratchpad>/<project>-<ticket-ref>-d<launch>/`, unique across boards and across relaunches of the same ticket, and tell the executor to keep every temporary file there and never write at the scratchpad root. Every generated executor definition carries the same rule, and read-only briefings point their scratch files at that directory too.
