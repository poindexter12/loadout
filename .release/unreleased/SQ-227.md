---
ref: SQ-227
title: Isolated worktrees allow heredocs that carry no git invocation
bump: patch
plugins:
  - sidequest
---

The isolated-worktree heredoc guard refused every heredoc, so a plain `cat <<'EOF' > "$SCRATCH/x"` write was blocked and a read-only executor, which has no Write tool, had no supported way to write scratch or evidence files. The guard now refuses only a heredoc that carries a git invocation: `git` as a program word in the shell part (for example `git commit -F - <<'EOF'`), or a git line inside a heredoc body fed to a shell interpreter (`bash <<'SH'`). A path or prose that merely contains "git" or "github", such as a session scratchpad under `~/Code/github.com/`, no longer trips it. The executor briefing, the read-only dispatch note, and the CLI help now say which heredocs are refused, and the read-only note names Bash heredoc or printf redirection into the scratchpad or verification directory as the supported write path.
