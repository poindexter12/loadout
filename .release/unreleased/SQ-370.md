---
ref: SQ-370
title: guard-destructive-git no longer spawns git for every Bash call, and the shared-tree commit and process-signal guards refuse on a busy board
bump: patch
plugins: [sidequest]
---

`guard-destructive-git` runs on every Bash call under the harness's 10s hook timeout, and a guard the harness kills returns no decision, so the call proceeds. It resolved the repository with `git rev-parse` before checking whether the command involved git at all, which cost 1.7 to 4.3s for a plain `ls` on a loaded machine. It now answers any command that names no git without spawning anything, and resolves the repository only for a command that matches a destructive pattern; push and tag checks still resolve their own repository. The push check also asks git for the upstream once per repository instead of up to three times.

`guard-shared-tree-commit` and `guard-process-signal` now fail closed under board lock contention, like the other enforcement guards. A raw executor commit in the shared checkout that the guard could not check against the board is refused with the standard board-contention message and a retry instruction, where it used to be allowed. `guard-process-signal` decides from the command text alone and does not read the board today, so its switch is defensive: it changes nothing until a board read is added there.
