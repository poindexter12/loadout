---
ref: SQ-185
title: "sidequest: verification_capture_required refusal now prints the exact verify-capture wrapper invocation"
bump: patch
plugins: [sidequest]
---

The `verification_capture_required` refusal (raised when submit finds no completed passed verify capture for the pinned command, ticket, and dispatch attempt) now prints the exact `node "<plugin>/lib/verify-capture.js" --base64 <encoded verify> --project "<repo>" --ticket "<ref>"` wrapper invocation when the project is known, resolved from the running plugin's own path rather than a hardcoded version directory, with the pinned verify command pre-encoded. Before this fix, an executor who lost the dispatched wrapper command after context compaction had no way to recover it from the refusal, the CLI help, or the launcher, and needed orchestrator help to rebuild it from `capturedVerifyCommand()`. When the caller has not threaded the project path through, the refusal still hands back the resolvable script path and pre-encoded command, plus explicit guidance naming exactly what `--project`/`--ticket` values to append to bind the capture to that ticket and attempt.
