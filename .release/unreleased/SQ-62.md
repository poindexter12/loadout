---
ref: SQ-62
title: Derive the full-suite phase budget from capacity the machine actually has, not the cores it owns
bump: patch
plugins: [sidequest]
---

`plugins/sidequest/scripts/test-full.mjs` scaled its functional phase budget by `480_000 * (maximumTestConcurrency / testConcurrency)`, so the allowance SHRANK as core count grew: every machine with 8 or more nominal cores landed on 480000ms, the tightest value in the curve, while a 4-core runner got 960000ms. `os.availableParallelism()` reports cores that exist, never cores that are free, so a 10-core developer machine at load 27 selected concurrency 8 and therefore the least wall clock precisely when it had the least real capacity. Three consecutive local runs died on that deadline, two tickets were hand-delivered because the gate was unpassable, and one release shipped with the suite skipped.

The budget now derives from effective workers — `cores * concurrency / (concurrency + loadAverage)`, the share fair scheduling actually grants — and the 480000ms constant is named for what measurement showed it to be: the EXPECTED duration of eight effective workers, not a deadline. Multiplying phase duration by effective workers gives a work constant of 3749 s*workers on a contended 10-core macOS box and 1212 s*workers on a 4-core ubuntu-latest runner, against the constant's own 3840 s*workers; the old code used an expectation with 2% of headroom as its deadline. The deadline is now 1.5x the expectation, the ceiling moved from 1200000ms to 2400000ms so the model survives the load band a shared machine really runs at, and the slowness warning fires against the expected duration instead of a fraction of the budget so a duration regression still shows up on a machine whose budget the ceiling has truncated. An idle machine reports a load average of 0, where effective workers collapse to the worker count, so this is a generalization of the core-count model rather than an inflation of it, and Windows — whose `os.loadavg()` is always zeroes — lands on that same branch.

`SIDEQUEST_FULL_SUITE_PHASE_BUDGET_MS` is new and widen-only: it can raise the budget past the ceiling for a machine busier than the model allows for, announces every decision it makes on stderr, and refuses any value that would shorten, zero or disable the deadline, so it cannot become a way to pass the gate without running it. The timeout and warning copy now report the observed load and the effective capacity it left, and the timeout says outright that the files reporting a still-pending promise resolution were cancelled by the kill rather than failed — a reading that had repeatedly been quoted as a failure count. Test-infrastructure change with no runtime behavior difference, but user-visible to anyone running the sidequest suite on a busy multi-core machine, where the gate was previously unpassable with no supported way to run it.
