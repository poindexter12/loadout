---
ref: SQ-98
title: Bug and feature tickets can mirror themselves to GitHub issues, filtered and sanitized
bump: minor
plugins: [sidequest]
---

Only a hand-linked ticket reached GitHub. Everything else the board knew was report-only, so a project's issue list showed whichever issues someone had remembered to link and nothing else. Keeping it honest meant filing the issue by hand and then linking it by hand, for every defect worth telling users about.

A board can now mirror the user-meaningful part of itself. `board_config` takes an `issueMirror` holding a filter over ticket labels, categories, and stories; a matching ticket gets an issue on the origin repo. It is off until that filter exists, because the useful part is the filtering: an issue list flooded with internal fix-ups, reviews, spikes, and planning tickets is worse than one that is merely incomplete. Review, audit, research, lookup, exploration, planning, and grooming categories never match on their own, so opting a board in cannot accidentally opt in its scaffolding.

Mirroring creates the issue and records an ordinary external link, the same record hand-linking writes. The existing linked-issue sync owns it from there, so status labels, the release marker, and close-on-done all keep working through one path rather than two, and a ticket already linked by hand is left alone. The stored link is also the idempotency key, so a rerun never files the issue twice.

The issue is a rewrite rather than a copy, and the rewrite is deliberately narrow. Two fields are published, the title and the description, named in an allow-list rather than filtered from the whole ticket, so a field added to tickets later cannot start leaking by default. Both are scrubbed of board refs, board slugs, absolute paths, hostnames, session and worktree identifiers, tokens, cost figures, and other projects' names. A rendering that still trips the detector after scrubbing is skipped with a warning instead of published, which is the behavior worth having when the alternative is a public repository.

Planning stays free. The mirror decides what it would create from board state alone, so the dry run that already runs at SessionStart costs no additional GitHub call and prints what it would file. Only `audit --apply` creates anything, which matters most the first time a filter is enabled: every matching open ticket is mirrored on that apply, and the dry run is how you find out what that means before it happens.
