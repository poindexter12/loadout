---
ref: SQ-287
title: Submit admits a candidate built on the ticket's named base ref
bump: patch
plugins:
  - sidequest
---

A candidate built on top of the base ref its ticket names (SQ-286, for example an open pull request's head) had no submit route: with no base the admitted range was measured from the integration target and swallowed the PR's own out-of-scope commits, and `base: <PR head>` refused `unrecognized_base` because that head is not on the integration target. Submit now treats the commit recorded in `dispatch.baseRef` as the range boundary for an isolated dispatch: the default range starts there, and an explicit base naming it is approved, so scope is checked over base..candidate only. A ticket that names no base keeps the previous rules. Integration still targets the board's integration branch; delivering such a candidate onto the named PR branch is not automated here.
