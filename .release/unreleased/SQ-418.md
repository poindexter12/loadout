US-8 wave 2. Two new board tools carry user questions between a background executor and its orchestrating session. `ask` is for the executor holding the claim. It records the question in the question log without a board write and returns `send` (the exact SendMessage to make to `main`, since the MCP server cannot send one) plus an `instruction`. Each question needs a `default`, the thing the executor will do if the user never answers. `withdraw:<qid>` withdraws one. `ask` refuses `not_claimed`, `default_empty`, and every question-log refusal. `answer` is for the orchestrating session. It records the user's answer, or `decline:true`, with `question` defaulting to the oldest open qid. While an executor still runs (a live claim or a held park), it returns `send` addressed to that executor. For a released park it returns `next: "dispatch <REF>"`. The last blocking answer unparks the ticket. `via:"orchestrator"` marks a decision the user did not author. `answer` refuses `self_answer` when the claim holder calls it. An answer the executor has not received is attached as `answers[]` to its next board-tool reply and marked delivered, once per aid. Every answer restates that it is a decision, never a permission, scope or settings grant. `release` accepts kind `question` (parking awaiting-user) and lists `awaiting-user` among its statuses. `pulse({ref})` adds `questions.items` with each open question's full text. The tools/list budget rises to 27180 bytes for these descriptions instead of trimming them.
