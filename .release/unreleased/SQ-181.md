---
ref: SQ-181
title: "sidequest: the negative-control failure classifier no longer keyword-matches free-text comment prose"
bump: patch
plugins: [sidequest]
---

The regression-proof check's negative-control classifier scanned an executor's entire comment body for the phrases "import error" and "collection error," so unrelated prose stating the failure was *not* one of those (for example, "none is an import or collection error") was misclassified as a reported import/collection failure and the completion was wrongly refused. The classifier now scopes its match to the `[sidequest:negative-control]` marker line's own reported evidence rather than the whole comment, and additionally ignores a match preceded by a negation word (none, no, not, never, isn't, without, ...) on that line, so a negative-control report that explicitly rules out an import/collection error is no longer rejected as one.
