---
ref: SQ-133
title: Hooks no longer stall on the board database lock, and the security guards fail closed under lock contention
bump: patch
plugins: [sidequest]
---

Hooks no longer stall behind another process's board write (SQ-125). Opening the store on an initialized board is now read-only: the schema check and seed refresh only look, and write only when something is actually stale. A hook waits at most once, for 1.5s, for a busy board lock, then allows the event without its board check and says so on stderr. The MCP server keeps its three 15s waits, and WorktreeCreate keeps its 120s timeout.

The security guards (guard-destructive-git, guard-shared-checkout-git, guard-worktree-isolation, force-exec-bypass) no longer allow a call they could not check. When the board lock stays busy past the hook budget, they deny the call. The deny message names the board lock contention and asks for a retry in a few seconds. Holding the board lock can no longer walk a guarded call past these guards. Calls that never need the board, like read-only git, tags, feature-branch pushes and non-git Bash in the git guards, are still decided without it. guard-home-delete and every other hook still fail open.

A long-lived store handle, such as the MCP server's, now rechecks the read-only category seeds whenever another connection commits, and a seed that a writer stores unflagged after open no longer stays stale. The upgradeSchema script is now pinned by hash to CURRENT_SCHEMA_VERSION in the test suite, so a schema edit that ships without a version bump fails the build.
