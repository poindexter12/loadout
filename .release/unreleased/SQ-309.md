---
ref: SQ-309
title: Shared-tree dispatch refuses a session rooted in another repository
bump: patch
plugins:
  - sidequest
---

A `sharedTree:true` dispatch whose spawning session is rooted in a different repository than the board's project (an orchestrator in repo A dispatching onto repo B's board) is now refused at `dispatch`, naming both roots. A shared-tree spawn carries no isolation and no cwd, so that executor used to inherit repo A and release on its worktree preflight. The refusal tells the caller to dispatch without `sharedTree` (the board then provisions an isolated worktree of the project) or from a session rooted in the project; when worktree isolation is disabled on that board it names only the latter. A subdirectory of the project checkout still counts as the checkout. Separately, `recoveryEvidence` on a ticket with nothing in flight now says no recovery is needed and to dispatch again without it, instead of only "not an active attempt".
