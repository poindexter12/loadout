---
ref: SQ-202
title: "sidequest: verify validator no longer reports names the command binds itself (for/select, read, local/export/declare, assignments, arithmetic) as unset environment variables (#19)"
bump: patch
plugins: [sidequest]
---

The unset-environment-variable check read every `$NAME` in a verify as an environment reference, so `bash -c 'for p in "alpha" "beta"; do grep -qF "$p" README.md || exit 1; done'` was refused as `invalid_verify`. A small shell lexer now finds the names a verify binds before reading them: assignment words (also after `env`), `declare`/`export`/`local`/`readonly`/`typeset` operands, `for`/`select` names, `read` targets (skipping option arguments), and arithmetic assignments in `((...))` and `$((...))`. A binding covers only later reads in its own scope or a nested one (a quoted `bash -c` script, a command substitution), so a double-quoted `$p` the outer shell expands before an inner loop exists, a subshell's assignment, and genuinely ambient names such as `$HOME_DIR_X` are still reported. The scan runs once per verify and is linear in its length.
