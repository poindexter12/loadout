US-8 wave 1. The dashboard server gains three read endpoints over the per-project question log. `GET /api/questions?project=<slug|all>&state=open|answered|declined|withdrawn|all&ref=&limit=&before=` lists questions newest first, with question text, ticket, seq, asker, state, blocking, asked and answered times, time to answer and `via`. It never returns answer text, `preview` or `bodyRef`, and a test asserts that. `GET /api/questions/<qid>` returns one full record: options, default, answer metadata (aid, via, whether the user wrote it, size, inline or body), the supersede chain and the event trail, with no answer text. `GET /api/questions/<qid>/answer` returns the answer text only when asked for. It reads `bodies/<aid>.txt` for a long answer, and `aid=` picks a superseded one. Reads keep an in-memory fold per project that advances by only the new bytes, and cache archived segment indexes, so a request never rereads the whole log. They touch nothing in the store except the lock-free `readMeta`, so they never take the board lock. Answering from the dashboard comes in a later wave.
