---
ref: SQ-184
title: "sidequest: an unrecognized_base refusal's remedy no longer names the base it just rejected"
bump: patch
plugins: [sidequest]
---

When a ticket's recorded dispatch base fell off the integration target (for example, a release commit that was on main at dispatch time and later got rolled back by `cut.mjs`), submitting with that base was refused `unrecognized_base`, but the refusal's own remedy text told the executor to "use the recorded" base commit — the exact commit that was just rejected, leaving no correct next action. `submissionRange` now reports `dispatchBaseResubmittable`, computed from real git ancestry against the current integration target, and the refusal's remedy uses it: when the recorded dispatch base would itself still pass the check, the remedy names it as before; when it would not, the remedy instead says to rebase the worktree onto the current integration target, re-run verify-capture, and resubmit with no base override.
