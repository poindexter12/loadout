---
ref: SQ-171
title: A continuation executor can bind its runtime identity and write in the worktree it was handed back
bump: patch
plugins: [sidequest]
---

A continuation resumes a worktree the board retained from an earlier attempt, so its dispatch is bound to that checkout by the continuation itself and never records the `WorktreeCreate` facts an ordinary isolated dispatch does. Every route that bound a runtime agent id from an `agent_id` alone, which is the only runtime identity Claude Code's hook payload carries for a dispatched executor, accepted an observed checkout only as those creation facts. So a continuation executor could claim its ticket and then never bind.

An unbound identity holds no write lease anywhere, including the retained worktree it was handed. The refusal that followed named one lever, `dispatch` with `recoveryEvidence`, and that route declines a dispatch whose claim is still held, on purpose: evidence retires an attempt whose runtime is gone. A live claimed executor was left able to neither write nor recover, and the right move for it was to release the ticket rather than work around the hook.

A dispatch's bound checkout is now read from whatever bound it. A completed creation target, a continuation's retained lease, and a live-claim recovery all record the same five immutable facts about a reserved path that a runtime had to be standing in to report, so all three are equally good evidence of identity. A recovered live claim was blocked the same way and is fixed by the same reading.

The agreement runs the other direction too: a continuation's runtime now binds only in the worktree the board holds it to, so the claim and the write lease can no longer name different trees. Its revision is deliberately not compared, because a continuation's first act is to bring the retained checkpoint forward onto the new baseline. A continuation that does land in some other checkout is still refused, but by the refusal that names the worktree to move to, which is a lever that works while the claim is live.
