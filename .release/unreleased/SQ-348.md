---
ref: SQ-348
title: Dispatch names higher-priority ready work it is skipping
bump: minor
plugins:
  - sidequest
---

`dispatch` now checks the board's priority order. When a ticket is dispatched while unblocked, undispatched ready work at a strictly higher priority is waiting, the result carries a `higherPriorityReady` list of those refs and a `dispatch priority:` warning that ranks with the defect warnings, so a crowded result never drops it. Blocked tickets, tickets parked on a submission or awaiting an oracle, and tickets whose own dispatch is already in flight do not count as waiting, so dispatching a mixed wave in priority order stays quiet. The dispatch still goes ahead. A new `priorityOverride` reason (`--priority-override` on the CLI) records why a ticket goes first anyway, such as the user naming it, and silences the notice for that attempt. The default `ready` rows now carry each ticket's priority, and the `ready` tool says that waves group by file overlap, not priority.
