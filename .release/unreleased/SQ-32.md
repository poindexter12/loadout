---
ref: SQ-32
title: "sidequest: stop minting ticket refs that release history already shipped"
bump: patch
plugins: [sidequest]
---

A board ref and a release-fragment ref are two minters over one number space, and neither knew about the other. The board counter was a bare `meta.seq + 1`, so nothing stopped it handing out a ref that a shipped changelog entry already owned. This repo is already in that state: its board counter sits at 327 while `CHANGELOG.md` names 960 refs up to SQ-2596, so every ticket filed from SQ-822 onward would have landed on released history. The same gap at the release end let one ref ship twice for unrelated work, because the cut skips a fragment only on an exact content fingerprint of ref, title, commit and body, and a different title is a different fingerprint. Six refs in this repo's own changelog carry two distinct titles that way, SQ-21 and SQ-22 among them.

Minting now steps over every number that `CHANGELOG.md` or `.release/unreleased/` already names for the board's own prefix, and persists where it landed. It skips forward rather than flooring to the highest released ref: flooring would jump this board from 327 to 2597 and abandon 2270 free refs in a single mint. A board that is not a release repo, or whose changelog cannot be read, keeps minting from its own counter rather than failing. `scripts/release/note.mjs` refuses a ref `CHANGELOG.md` already shipped under a different title and says which titles own it, while re-noting the same title stays allowed for amend flows; `--allow-shipped-ref` overrides it deliberately.

Folding one board into another also stops renaming tickets that had no conflict. A merge used to re-mint every source ref, which invalidated every comment, commit message, branch name and handoff that named the old one; it now keeps a ref the destination does not already hold, counting archived tickets as holders, and re-mints only a genuine collision. The destination counter is lifted above every kept ref first, so a re-mint cannot land on a ref one of its own siblings is keeping. Ticket refs also read their prefix from project metadata now, defaulting to `SQ` for every board that predates the field, which leaves existing refs untouched.
