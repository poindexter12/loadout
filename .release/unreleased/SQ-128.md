---
ref: SQ-128
title: Shared-checkout git guard matches git as an invocation, so a checkout path used only as an argument is no longer refused
bump: patch
plugins: [sidequest]
---

The guard that stops a dispatched executor from mutating the shared checkout now reads `git` only where it is the program word at a command boundary, and skips any match that sits inside a quoted argument. A command that merely passes the shared checkout path, such as `--project <checkout>`, `git fetch <checkout> main`, a directory whose name contains `github`, or a quoted note that reads like a git command, is no longer refused.

The same pass closes two missed refusals in the other direction: the guard now resolves every git invocation in a command against its own `-C` or the nearest preceding `cd`, so `cd <checkout> && git reset --hard` and a mutating invocation that follows a read-only one are refused instead of allowed. The refusal text now states that passing the checkout path as an ordinary argument is allowed.
