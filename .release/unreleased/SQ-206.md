---
ref: SQ-206
title: "sidequest: a command verify that starts with docker, podman or any other executable is no longer refused as not runnable"
bump: patch
plugins: [sidequest]
---

`add` and `update` used to check a command verify's first word against a fixed list of tools, so `docker build ... && docker run ...` was refused with "Verify must start with a runnable command" while `cd . && docker ...` passed (poindexter12/loadout#23). The first word is now checked by shape instead: any executable name (letters, digits and `_ . + -`, not starting with `-`) or any path is runnable. Prose is still refused: a leading prose verb such as `check` or `confirm`, and a capitalised word such as `Run`, `Make` or `Tests`, which is how a sentence starts rather than how a command is spelled. That also means `Make sure the build passes` is now refused, where the old case-insensitive list let it through. The refusal names the word it read as prose and no longer implies a list of allowed tools.
