---
ref: SQ-252
title: A slow shim supervisor stop is waited out and escalated instead of failing the update
bump: patch
plugins: [model-gateway]
---

Stopping the shim supervisor used to allow a flat 3 seconds, so on a loaded machine `update-loadout` reported `could not restart shim supervisor` for a SIGTERM that had in fact worked, and a second identical run finished fine. An interactive stop (`setup`, `update-loadout`, `restart`) now waits for the worker drain it is actually waiting on (`CODEX_GATEWAY_DRAIN_TIMEOUT_MS`, never under 12 seconds), then escalates to SIGKILL rather than giving up. The SessionStart hook's quiet stop keeps its short wait and never escalates, because an unconfirmed stop there is already handed to the detached recovery controller. When a supervisor really does survive both signals, the refusal now says the stop is still in flight and to run ensure again, instead of naming a stop command the updater had just run itself.
