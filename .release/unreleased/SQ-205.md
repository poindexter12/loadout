---
ref: SQ-205
title: "sidequest: a session stranded by a newer board schema is told which version migrated it and to run /reload-plugins"
bump: patch
plugins: [sidequest]
---

The board database is shared by every session on the machine, so the first process running a newer sidequest migrates it out from under sessions that still have an older one loaded (#22). Those sessions used to fail every Board MCP call with a bare "Sidequest database schema N is newer than supported schema M." The refusal now says whether it refused to open the board or refused a write, names the sidequest version this session has loaded, names the sidequest version that migrated the board to that schema and when (when that was recorded), and tells the session to run /reload-plugins (or restart Claude Code) and retry, noting the call changed nothing. It also carries `code: SIDEQUEST_SCHEMA_NEWER` and the versions as structured fields. To make that possible, every migration now records its plugin version, schema version, and time under the `schema_migrated_by` meta key; opening an already-current board still writes nothing. A refused open now closes its database handle instead of leaking one per retried call. Sessions already running sidequest 5.3.x or older still show the old message when a newer version migrates, because the old code produces it; the named migrator appears from the first migration run by a version that includes this change.
