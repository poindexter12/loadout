---
ref: SQ-180
title: "sidequest: negative-control test-name matching unescapes source string literals instead of demanding literal backslashes"
bump: patch
plugins: [sidequest]
---

The negative-control check that makes an executor prove new or changed tests fail on base was reading test names straight out of the source file's string literal, backslash escapes and all. A test named with an escaped quote in source (`'the gateway\'s wrapped proxy retries once'`) was demanded back as the literal `gateway\'s`, a string no test runner ever prints, forcing the executor to fabricate an unreal marker just to satisfy the check. `changedTestNames` now unescapes JS string-literal escapes (`\'`, `\"`, `` \` ``, `\\`, `\n`, `\t`, `\r`, `\uXXXX`, `\u{X}`, `\xXX`, and any other escaped character) before recording the expected name, so the expected name matches what the test runner actually prints.
