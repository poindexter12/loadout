# Architecture

Last Updated: 2026-10-10

Structure (the folder tree, entry points, and per-module dependencies) lives in the graph: `graphify-out/GRAPH_REPORT.md` and `graphify query|explain|path`. This document covers the judgement the graph cannot hold: why the boundaries are where they are.

## Repository shape

The repository is a plugin marketplace. Six plugins are published: `plugins/sidequest`, `plugins/observability`, `plugins/model-gateway`, `plugins/live-rules`, `plugins/codebase-mapper`, and `plugins/quartermaster`, with marketplace metadata in `.claude-plugin/marketplace.json`. `plugins/test-support` is shared test support, not a plugin. `examples/` holds small example projects, not production plugin runtime, so a path there is never a plugin's code however much it looks like one.

## Runtime flow

Claude Code loads runtime files declared by plugin manifests and hook manifests. Sidequest builds TypeScript from `plugins/sidequest/src/` into committed `agents/`, `lib/`, `bin/`, and `hooks/` output. `plugins/sidequest/scripts/build.mjs` runs `scripts/generate-bundled-agents.mjs`, which derives the stable executor markdown roster from `lib/agentsync.js`; runtime manifests point at the generated files. Its MCP entry is `plugins/sidequest/bin/sidequest-mcp.js`, configured by `plugins/sidequest/.mcp.json`; hooks are registered in `plugins/sidequest/hooks/hooks.json`. The MCP server exits on stdin EOF, and also when an initialized client goes silent for a minute and fails to answer a JSON-RPC `ping`, which is what reclaims a session a host abandoned without closing the pipe; any client message resets that timer, so an actively used server never pings. CLI and MCP handlers share store operations in `plugins/sidequest/src/lib/store.ts`. The typed lifecycle reducers and worktree lease decisions live under `plugins/sidequest/src/lib/kernel/`; transports adapt repository, immutable-revision, process, and checkout facts into that kernel. Checkout identity is one of those facts and is read from disk rather than spawned: `kernel/worktree.ts` exports `checkoutLayout`, which derives the facts from git's on-disk layout, because the hook paths that need them were spending most of a 10-second hook deadline on `git rev-parse` processes on a contended host. Process spawns remain the deliberate fallback wherever the layout cannot be read confidently, including an unborn HEAD and a path that no longer exists, where walking up would otherwise report the enclosing checkout as the removed worktree. Release and test phases use `plugins/sidequest/scripts/owned-process-tree.js` with its detached supervisor to retain process ownership through cleanup. The optional `hooks/fn/compaction.js` function-hook module protects dispatch and briefing results across third-party transcript replacement; `src/hooks/shared/live-refs.ts` coordinates Stop-hook state with that module, while `src/lib/backup-refs.ts` owns auditable checkpoint refs outside the candidate namespace.

Sidequest persists board state in SQLite and serializes mutations per board. The orchestration loop covers dispatch, routing, categories, executors, claims, submissions, scope enforcement, and worktree management through typed store and lifecycle modules. Database migrations record `schema_migrated_by` so an older session can explain a newer-schema refusal. Stable executor definitions are loaded from the package's `plugins/sidequest/agents/` roster; session-start maintenance and `models sync-agents` migrate only marked legacy generated files and preserve custom or unreadable agent files. Confirmed terminal process evidence can release the exact dead claim or pre-claim dispatch binding; live and unknown owners remain protected, and ownership is checked before forced submission or release mutations. `plugins/sidequest/src/lib/agentsync.ts` compiles dispatch briefings and ships them whole; a briefing larger than Claude Code's Bash output cap is written to a file under the store home and the executor is told to Read it. `mcp-read.ts` exposes `context_page` for paging list/comments rows, and `mcp-shared.ts` derives every read-result ceiling from Claude Code's 25,000-token MCP result cap via `context-packet.ts` (no self-chosen byte budgets). The dashboard is a separate Svelte/Vite app that talks to the local server over HTTP `/api/*` and polls state.

## Dispatch lifecycle

The dispatch lifecycle freezes the story contract, provider/model identity, source baseline, and briefing snapshot at preparation time; the briefing carries its full text, so `context_page` pages only board reads, never briefing sections. A non-default provider route travels in the pinned executor definition's own `model:`/`effort:` frontmatter rather than a prompt marker, and a `[sidequest-route ...]` marker on the spawn prompt is refused, because a marker could override the pinned effort the board chose. `lib/exec-names.ts` derives one definition name per (model, effort) pair and folds every non-alphanumeric run uniformly, so window-suffixed ids such as `claude-gpt-5.6-terra` and `claude-gpt-5.6-terra[1m]` pin distinct definitions instead of collapsing onto whichever synced last. Submission is a terminal executor transition: the store atomically parks the immutable candidate, releases the claim, and prevents that executor from resuming it. Review rejection preserves the candidate and its evidence; repair uses a fresh candidate identity, and only an integrated replacement can supersede the rejected submission. Because a rejected candidate is parked and never integrated, it is excluded from the duplicate-submission scan, so a repair branched from it carries the range forward instead of being refused `duplicate_submission` and forced into an undocumented squash. Scope refusals over a release fragment are classified rather than blanket: `foreignReleaseFragmentDiagnosis` names what is actually missing (the `related` link, the rejection, or neither), and a related review-rejected fragment is admitted with deletion checking deferred to the commit gate. Worktree creation, write, resume, and cleanup each require an immutable lease binding. Cleanup additionally requires terminal liveness, the original checkout-instance marker, and a registered worktree owned by the store.

Quartermaster bootstraps project configuration, updates Loadout installs through the stable Model Gateway updater launcher, migrates legacy gateway state, and reports effective Codex `autoCompactWindow` settings. Its SessionStart and UserPromptSubmit freshness checks are advisory; its Stop update check refreshes marketplace freshness and reports available updates or plugin reloads without installing or blocking. It hands telemetry setup to Observability, which owns the observer, Collector, sinks, and statusline. Model Gateway's `plugins/model-gateway/bin/model-gateway.js` maintains the local proxy, shim, readiness state, catalog, and model routing for `claude-gpt-*` and `claude-grok-*` models, while retaining legacy `claude-codex-gpt-*` compatibility; it can bind an ephemeral shim port, record serving version, and defer restart; supervision enforces a never-downgrade invariant, so a stale session's `ensure` leaves a newer serving shim running, same-marketplace/plugin cache siblings can be replaced, foreign installs stay untouched, spawns resolve the newest installed CLI, and the shim's `/restart` refuses adopting an older worker script. Shutdown waits for pending PID-record writes and supervised children, while fixture shutdown can signal the supervisor directly. Project wiring is declined rather than forced: when the settings definition that wins Claude Code's precedence holds a base URL that is neither this plugin's nor an Anthropic endpoint, `writeEnv()` refuses every write it was not asked for by name, so `setup`, `ensure`, and the automatic wiring paths all leave a project pointed at another gateway, relay, or proxy alone instead of overwriting `.claude/settings.local.json`. The refusal precedes legacy project-settings migration, which would otherwise move gateway keys inside a file meant to stay untouched; `env --write-project/--write-user` pass an explicit flag and still overwrite, and removal only ever deletes keys this plugin owns. The pin advice and SessionStart notice name the other endpoint instead of recommending a rewire.

Observability provisions Grafana dashboards from the local opted-in-project registry. It was split out of Workbench, but the `workbench-observer` service name and `workbench_` attribute prefix stayed behind deliberately, because shipped Grafana queries and already-collected data depend on them. Its model pricing handles Astra's per-request short/long input tiers and keeps unpriced model usage visible as token volume instead of inventing a dollar total. Live-rules injects matching developer rules at prompt and edit time. Codebase-mapper injects `.claude/.codebase-info/INDEX.md` at session start and enforces main-session map updates through PreToolUse and Stop hooks.

Codebase-mapper splits ownership of the map where a graph exists. `hooks/lib/graph-mode.js` is the read-only detection contract: the presence of `graphify-out/GRAPH_REPORT.md` alone puts a project in graph mode, and the hooks never run or install graphify. In that mode `inject-context.js` adds one paragraph sending structural questions to `graphify query|explain|path` while keeping these documents as the source for conventions, patterns, and onboarding, and the subagent variant additionally forbids refreshing the graph; non-graph output stays byte-identical. `map-documents.js` treats a `.map-state.json` declaring `structure: "graphify"` as covering narrative documents only, so the three retired structural documents being absent is expected rather than stale. graphify is an opt-in Python `uv` tool whose lifecycle Quartermaster owns: `plugins/quartermaster/bin/graphify.js` is the single place pinning the distribution name, executable name, version floor, and the CLI surfaces the mapper invokes, and the doctor probes `graphify --help` for all five so an upstream rename fails loudly instead of silently inside a subagent. Setup offers it only alongside codebase-mapper and only after finding `uv`; `update-loadout` upgrades it only when `uv tool list` already names it, and never installs it. Quartermaster's miner reads outside the repository: `plugins/quartermaster/lib/scan.js` selects transcripts from `~/.claude/projects/<slug>/`, including per-session `subagents/*.jsonl`, and `lib/signals.js` reduces them to a bounded JSON aggregate on stdout. Its per-session tallies and decision ledger live under `~/.claude/quartermaster-state/`, so nothing is written into the project.

`sandbox/windows/` is a maintainer-only, gitignored (`.gitignore`: `/sandbox/`) Windows Sandbox clean-room harness: it generates an isolated `.wsb`, maps only its bootstrap directory read-only, and validates its PowerShell scripts with `Test-ToolshedSandbox.ps1`. It has no public docs page and is never pushed to the shared repository.
