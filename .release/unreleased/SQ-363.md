---
ref: SQ-363
title: worktrees sweep reclaims settled legacy worktrees and branch-only agent orphans, and names the owner of what it keeps
bump: patch
plugins: [sidequest]
---

A legacy worktree (no board lease identity) with uncommitted changes was `legacy_unreclaimed` forever, even when its branch was already merged or patch-equivalent to the integration branch. It is now classified `legacy_backup`: once it is old enough and settled, `worktrees sweep --yes` writes its dirty edits to the worktree-backups store (now with `--binary` patches) and removes it, along with its branch.

Branch-only `worktree-agent-*` refs were assessed in a window capped by the number of registered agent worktrees, so a repository whose agent trees were all gone assessed none of them. Only an explicit candidate bound now limits branch assessment, and merged or patch-equivalent orphans are pruned under `--yes`.

A legacy worktree or orphan branch whose commits are neither merged nor patch-equivalent is still kept, but its report entry now carries `ticket` (from the dispatch agent id, or a known ticket ref in its commit subjects), a `trace` command (`git cherry -v <upstream> <branch>`) and a `discard` command, so a human can finish the trace.
