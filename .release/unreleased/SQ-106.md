ref: SQ-106
title: PR delivery closes tickets when the wave PR merges
bump: minor
plugins:
  - sidequest
---

With `deliveryChannel.mode: "pr"`, calling `integrate` again on a wave that awaits merge now asks GitHub what became of its PR. A merged PR whose merge commit is reachable from `<remote>/<target>` closes every participant through the normal integration close, with the merge commit as the delivery commit and the PR URL as evidence, so no manual `groomClose` is needed and audit release detection reads the merge commit. An open PR with pending checks stays `awaiting-merge`. Failing required checks refuse `wave_ci_failed` and name the failing checks. A PR closed without merging refuses `wave_pr_closed_unmerged`. A merge commit that is not yet on the remote target refuses `wave_merge_unreachable` and records nothing.
