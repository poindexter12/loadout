---
ref: SQ-346
title: A health probe aimed at an unassigned port no longer answers from port 80
bump: patch
plugins:
  - model-gateway
---

A gateway whose proxy port was unassigned or misconfigured could report itself
healthy on the strength of an unrelated web server. Node's http client turns an
explicit `:0` in a URL into the default port 80, so the `/v1/models` health probe
silently interrogated whatever was listening on `127.0.0.1:80` and accepted its
200 as the gateway proxy answering. On a machine running a local web server that
made `ensure` conclude the gateway was already up and skip starting its
supervisor.

The probe now refuses an unassigned port before issuing any request, and
`fetchUrl` and `postJson` reject an explicit port 0 outright rather than falling
back to the default port, so a drain or restart request can never reach a
stranger either. Probe failures name the cause: `no proxy port assigned
(port 0), so nothing could be probed`.
