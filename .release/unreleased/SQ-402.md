---
ref: SQ-402
title: "Run non-executor Agent spawns in the background instead of refusing them, with a settings-based foreground list"
bump: minor
plugins: [sidequest]
---

The Agent guard no longer refuses main-session spawns of agents that are not Sidequest executors. A
third-party plugin agent (such as `sg:spec-interviewer`), `general-purpose`, or a project agent now runs
with `run_in_background: true` and is otherwise untouched: its own permission mode, model, and isolation
are kept. This holds in routed, unrouted, and unregistered projects alike.

Agent types that must stay in the foreground go in Claude Code settings under
`"sidequest": {"foregroundAgents": [...]}`, read from the project's `.claude/settings.local.json`, then
`.claude/settings.json`, then the user `settings.json`. The most specific file that defines the key
replaces the others' lists. `Explore`, `claude-code-guide`, and `statusline-setup` stay foreground as before.

Dispatched-executor validation is unchanged. A Sidequest-named agent type that is not a current executor
is still refused, as is an ordinary agent whose prompt carries a dispatch briefing or `[sidequest-...]`
marker. The per-session record that refused an Explore relaunch of previously denied generic work is gone
with the refusal it enforced.
