---
ref: SQ-76
title: Bind verification captures to the tree that ran, not to HEAD
bump: patch
plugins:
  - sidequest
---

A verification capture no longer certifies `git:<HEAD>` for code HEAD does not contain. The wrapper snapshots the working tree immediately before the command runs. A clean tree binds to HEAD as before. A tree with uncommitted changes, including `git checkout <rev> -- <path>`, is recorded against a `git-dirty-tree` identity (HEAD plus the exact modifications) and reported as diagnostic evidence that can never satisfy the submit gate. A clean-start capture whose tracked files change while the command runs is not recorded (`capture_candidate_dirtied`).
