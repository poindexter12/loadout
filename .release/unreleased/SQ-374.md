---
ref: SQ-374
title: PR delivery survives an integrate that dies while opening the wave PR
bump: patch
plugins:
  - sidequest
---

With `deliveryChannel.mode: "pr"`, `integrate` now records the PR open it is about to make on the wave before it pushes `sidequest/wave/<wave-id>`, and adds the PR to that record once `gh pr create` returns. If the process dies before it records `awaiting-merge`, the next `integrate` adopts what it left instead of refusing the existing branch: a pushed branch at the recorded head gets its PR opened without a rebuild or re-push (`resumed: true`), and a recorded PR that GitHub still reports at that head has auto-merge re-armed while open, is recorded `awaiting-merge`, and is reconciled in the same call, so a PR that already merged closes its participants (`adopted: true`). A wave branch or PR the record does not describe still refuses `pr_delivery_unavailable` and is never force-pushed. A failed `gh pr merge --auto` whose branch cannot be withdrawn now leaves the record in place so the next `integrate` adopts the PR and retries.
