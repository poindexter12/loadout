title: The comment tool tells agents to keep ticket comments short
bump: patch
plugins:
  - sidequest
---

The `comment` tool now says what a ticket comment should be: a short summary with pointers (log paths, commit shas, comment ids), not a full report or a dumped log. Its served description notes that executor briefings defer comment bodies past the 16 KiB briefing comment budget, so a long comment pushes earlier handoffs out of the next executor's briefing. The two tests that asserted every comment body appears verbatim in a briefing now assert the capped contract: the newest body inline, older bodies deferred to a `context_page` call that recovers them byte for byte.
