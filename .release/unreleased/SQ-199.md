---
ref: SQ-199
title: "sidequest: optional session.compact function-hook module keeps dispatch and briefing results under third-party compaction"
bump: minor
plugins: [sidequest]
---

A third-party compaction plugin such as fast-jev-compaction replaces the transcript itself, so a board `dispatch` result or a `sidequest-launcher.js briefing` output could come back truncated or dropped. Sidequest now ships an optional function-hook module (`hooks/fn/compaction.js`, listed under `modules` in hooks.json) that snapshots those results before compaction and puts back any the plugin beneath it truncated or dropped. A truncated result gets its full text back where it sits, and a dropped one goes back as fresh hook-built tool_use and tool_result messages, as a pair and in their original position, so the transcript's parent chain stays intact across `--resume`. A result that holds non-text content is left as the plugin had it. Each result is capped at 32 KiB and the total at 64 KiB, with a retrieval pointer past the cap. It also appends the board recovery pin to the compaction instructions unless the v1 marker is already there.

It is off by default. The new `compactionGuard` plugin option (`/plugin` config) takes `off` (registers nothing, and the Stop hook writes nothing), `auto` (acts only once a trace shows a non-core compaction plugin beneath sidequest), or `on` (always acts). It needs `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` and `sidequest@loadout` in `prependPlugins`. Without function hooks enabled, the module is skipped and the classic hooks are unchanged. When the option is not `off`, the Stop hook records which refs the board has closed in `<SIDEQUEST_HOME>/live-refs/<session>.json`, so results for closed refs are let go.
