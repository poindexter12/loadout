---
ref: SQ-286
title: A ticket can name the base ref its isolated worktree starts from
bump: minor
plugins:
  - sidequest
---

Tickets accept a `baseRef` on `add` and `update` naming a branch, `origin/<branch>`, tag, or commit, such as an open pull request's branch. An isolated dispatch of that ticket now forks its worktree from the commit the ref resolves to in the project checkout (a bare branch name also resolves through `origin/`), records it as `dispatch.baseRef`, and its briefing tells the executor to reset onto that commit instead of the integration target. Previously the worktree silently started from the integration target, so the PR's code was missing. Dispatch refuses, before minting a token, when the named ref does not resolve or when the dispatch would run in the shared checkout. Option-shaped or malformed refs are refused at filing. Clearing `baseRef` (empty string) restores the integration-target fork.
