Fixes #20. The verify-capture wrapper kept its own dispatch-only pin lookup while the recorder resolved the pin through the full submission rules (legacy ticket verify, orchestrator re-pin), so the wrapper could run a command, watch it pass, and then have the recorder refuse it with `capture=unrecorded reason=verification_capture_command_mismatch` and nothing else. The wrapper now asks the recorder (`recordVerificationCapture` with `preflight: true`, read-only) before running, so a command it runs is exactly a command the recorder accepts. A genuinely different command is still refused, before it runs. Any refusal the recorder returns after a run is now printed on a `capture-detail=` line. The mismatch message shows both commands bounded to 1200 characters, escapes every non-ASCII character so look-alike and invisible characters are visible, and names the first differing character with context on both sides. A verbatim dispatch encoding still round-trips byte for byte, including #20's own command with nested quotes and a `{20,}` quantifier.
