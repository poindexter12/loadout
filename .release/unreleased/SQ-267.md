---
ref: SQ-267
title: "sidequest: the worktree sweep rotates its candidate window, so an unremovable worktree no longer starves every one behind it"
bump: minor
plugins: [sidequest]
---

The sweep assessed at most eight worktrees per project per session, always the first eight of a stable name-sorted `git worktree list`. On a board whose first eight entries were permanently unremovable, candidates nine onward were never assessed in any session, ever. One project reached 81 registered agent worktrees and 22GB, with the oldest resident 413 hours, while every session reported the sweep finding nothing to collect. The budget was never the bottleneck: a sweep that drains its 2500ms still classifies a window it has already walked past.

The window now rotates from a per-project cursor persisted beside the existing project cursor, so each sweep resumes after the last worktree it assessed and an unremovable head costs one window rather than every window. The cursor is advisory and written once at the end of the project loop; losing it to a contended board repeats a window instead of dropping collection work.

Progress reporting now carries how much was assessed against how much exists. The budget-expiry notice reads "assessed 0 of 81" where it used to read a bare "planned 0, removed 0, skipped 0 (none)" — counts that an agent reasonably read as a verdict that nothing needed collecting, which is what SQ-70's reporter did before spending a run on the wrong defect. A completed sweep that plans nothing now says so explicitly, including how much of the backlog is still unassessed and the command that finishes it, where it previously produced no notice at all and left the next session unable to tell a sweep that ran from one that never did.

Two routes out of permanent residency open alongside it. A worktree holding committed-but-unintegrated edits had no terminal route at all: preservation was satisfied only by keeping it, which is why the oldest tree had sat for 413 hours. Past the salvage age those edits now go to `refs/salvage/<agent>`, the same mechanism the unintegrated route already uses, and the tree is collected. Separately, a continuation dispatch records a complete worktree binding over the checkout it retained but never a creation stamp, so cleanup identity read every continuation-bound tree as unknown and unreclaimable; identity now accepts that binding. Reclaiming an *unclaimed* dispatch's checkout still requires a real creation stamp, because a retained checkout was never the board's to recreate.

Liveness is unchanged in what it protects and now applies evenly: the hand-run `worktrees sweep` reads the live session checkouts the SessionStart hook has always passed, so the command the budget notice points agents at no longer protects a running executor's tree on its board claim alone.
