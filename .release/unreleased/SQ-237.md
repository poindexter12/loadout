---
ref: SQ-237
title: Hooks resolve a linked worktree outside the checkout to its repository's board
bump: patch
plugins:
  - sidequest
---

`findProject` now folds an unregistered absolute path through the same git-aware resolution the CLI applies to its cwd, so a linked worktree living outside the main checkout (a baude worktree, for example) resolves to the main repository's board. The Agent gate no longer denies such a session with "this project is not registered on a Sidequest board", and dispatch launch recording finds the board too. A path registered as its own board still keeps that board, and an unregistered repository still reports `not_found`.
